# Privacy Declarations

Telltale is self-hosted in the developer's Laravel Cloud account. Telltale itself does not sell data
or use it for tracking. The developer remains responsible for matching these baseline declarations to
custom event properties, optional identifiers, retention settings, and every other processor in the app.

## Apple Privacy Manifest

Add this usable baseline to the NativePHP app's `PrivacyInfo.xcprivacy`. It declares product
interaction, PHP diagnostic data, and Telltale's random per-install identifier for analytics. Telltale
does not use these categories for tracking and does not link them to a user by default.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>NSPrivacyTracking</key>
    <false/>
    <key>NSPrivacyTrackingDomains</key>
    <array/>
    <key>NSPrivacyCollectedDataTypes</key>
    <array>
        <dict>
            <key>NSPrivacyCollectedDataType</key>
            <string>NSPrivacyCollectedDataTypeProductInteraction</string>
            <key>NSPrivacyCollectedDataTypeLinked</key>
            <false/>
            <key>NSPrivacyCollectedDataTypeTracking</key>
            <false/>
            <key>NSPrivacyCollectedDataTypePurposes</key>
            <array>
                <string>NSPrivacyCollectedDataTypePurposeAnalytics</string>
            </array>
        </dict>
        <dict>
            <key>NSPrivacyCollectedDataType</key>
            <string>NSPrivacyCollectedDataTypeOtherDiagnosticData</string>
            <key>NSPrivacyCollectedDataTypeLinked</key>
            <false/>
            <key>NSPrivacyCollectedDataTypeTracking</key>
            <false/>
            <key>NSPrivacyCollectedDataTypePurposes</key>
            <array>
                <string>NSPrivacyCollectedDataTypePurposeAnalytics</string>
            </array>
        </dict>
        <dict>
            <key>NSPrivacyCollectedDataType</key>
            <string>NSPrivacyCollectedDataTypeDeviceID</string>
            <key>NSPrivacyCollectedDataTypeLinked</key>
            <false/>
            <key>NSPrivacyCollectedDataTypeTracking</key>
            <false/>
            <key>NSPrivacyCollectedDataTypePurposes</key>
            <array>
                <string>NSPrivacyCollectedDataTypePurposeAnalytics</string>
            </array>
        </dict>
    </array>
    <key>NSPrivacyAccessedAPITypes</key>
    <array/>
</dict>
</plist>
```

If the app calls `Telltale::identify()`, sends personal data in custom properties, or links the random
install id to an account, update `NSPrivacyCollectedDataTypeLinked` and the store answers accordingly.
Other NativePHP plugins may also require accessed-API declarations. Keep their declarations when
adding this baseline.

### Optional Mobile crash plugin

The planned crash package adds Crash Data, Performance Data and Device ID for app functionality.
These diagnostics are linked to the random Telltale install identifier, so its supplied manifest
uses `NSPrivacyCollectedDataTypeLinked=true`, without tracking. It conservatively merges that value
with existing declarations; it does not downgrade a host's tracking flag or remove analytics purposes.
The v1 baseline above remains the reference for apps without the crash plugin.

The plugin's NativePHP `post_compile` hook merges the shipped XML manifest into the app target,
after every plugin's project files and assets have been copied, preserving existing data types,
purposes, tracking domains and required-reason API entries across repeated builds. Invalid host XML
stops the build. The original file stays intact. Inspect the final archive's root
`PrivacyInfo.xcprivacy` and Xcode privacy report before distribution. See
[the crash guide](mobile-crashes.md) for placement sources and installation steps.

## App Store Privacy Label

Use these baseline answers for Telltale's automatic v1 capture:

| Apple category | Collected | Purpose | Linked to identity | Tracking |
|---|---:|---|---:|---:|
| Product Interaction | Yes | Analytics | No by default | No |
| Diagnostics / Other Diagnostic Data | Yes | Analytics | No by default | No |
| Other Identifiers (the install id) | Yes | Analytics | No by default | No |

The install id is generated by Telltale, resets on reinstall, and is never IDFV or Android ID. Declare
any custom event properties and optional opaque user id according to the app's actual use.

With the optional crash plugin, also declare Diagnostics / Crash Data and Performance Data for app
functionality, linked to the install identifier and not used for tracking. Include that linkage in
the identifier answer. These additions do not replace the app's other privacy disclosures.

## Google Play Data Safety

Use these baseline answers for Telltale's automatic v1 capture:

| Google Play data type | Collected | Shared | Purpose | Required |
|---|---:|---:|---|---:|
| App activity / App interactions | Yes | No by Telltale | Analytics | No; opt-out is available |
| App info and performance / Diagnostics | Yes | No by Telltale | Analytics | No; opt-out is available |
| Device or other IDs | Yes, random Telltale install id | No by Telltale | Analytics | No; opt-out is available |

Data is encrypted in transit with HTTPS to the developer-owned server. Install-scoped deletion is
available through Telltale's MCP or local Artisan administration. Telltale does not capture a hardware
identifier. Add disclosures for custom properties, `identify()`, or any onward sharing by the app or its
operators.

For crash-plugin apps, add App info and performance / Crash logs and Diagnostics, used for app
functionality. Collection remains optional through opt-out, with no onward sharing by Telltale.
The native store holds bounded reports for up to seven days before import or expiry. Opt-out
discards the native backlog as well as the client outbox; already uploaded data follows server
retention and install-deletion rules.
